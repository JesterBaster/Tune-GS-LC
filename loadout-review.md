# Inventory and combat loadout review

System version remains **0.0.1**. Reviewed against the local Angels Sword 0.13.1 catalog, supplied rulebook and the supplied character workbook. The website's rendered pages did not expose their rule text to the web reader; this implementation uses the previously collected complete catalog descriptions.

## Flaws found and addressed

- **Unrestricted equipped flags:** multiple armors and arbitrarily many weapons could contribute bonuses. Combat loadout now has left hand, right hand and body slots. Only valid, carried, positive-quantity slotted items contribute. Legacy flags populate a conservative initial loadout; conflicting legacy equipment is listed for review rather than deleted.
- **Hand conflicts:** two-handed equipment occupies both hands, disables the other selector, and asks before displacing its item. Cancellation leaves the equipment unchanged. The same Item cannot occupy multiple slots.
- **Burden was cosmetic:** carried burden above 10 now sets derived Rooted, zeroes effective speed, prevents spending AP on Speed, and blocks ordinary token movement, including outside initiative. Returning to the limit immediately restores movement capability. Movement reversal remains available; explicit forced movement can bypass this restriction with `asForced`.
- **Container storage was absent:** an Adventurer's Kit accepts 5 burden of eligible Adventuring Essentials, kit contents or a Northi Lantern. Normal/Deluxe Alchemy Rigs accept 2/5 burden of suitable alchemical consumables. Only one rig may be active. Selections reference owned Item IDs and quantities. Exemptions cannot exceed capacity or quantities owned and cannot be used twice. Kits/other burden-reducing containers cannot nest for exemptions. Containers still incur their own burden. Deleted containers and invalidated contents immediately lose their exemption; excess quantities count normally.
- **Mage Armor was only descriptive:** owning its catalog ability unlocks Light/Medium/Heavy armor, one frame modification (Barrier, Fortress, Manaweave or Protective Coating), and optional light-only Spidersilk. Mage Armor replaces body equipment's defensive effects, adds no burden, retains the physical inventory, and does not require armor proficiency. Modifications lock on application. Changes/removal cost 2 AP while in initiative. Application is limited to encounter start and cannot be repeated for free in the same encounter. Combat end expires it. Losing its granting ability immediately removes its effects.
- **Mage Armor side effects:** the frame modifiers affect Guard, Block, Evasion, Dodge, initiative and movement as described. Manaweave changes maximum/current MP by 3 without erasing prior MP spending. Spidersilk exposes a Fire-damage checkbox in defense chat, applying doubled incoming Fire damage before Guard. The Frame version of Barrier is used, not the separate B modification with the same name.
- **Item numbers/images:** numeric prices containing “Clim” or thousands separators are parsed correctly. Standard armor/shield statistics are initialized from the library; original variable cost and burden text remains visible on the Item sheet. Library images are used for new library/imported items. The inventory offers a bulk update for existing default icons without replacing custom artwork.
- **Stale import equipment:** replacing a character through Excel now clears its previous loadout references before resolving the new inventory.
- **Storage access:** zero-quantity items cannot be used. Items in lockers/backpacks cannot be used directly as carried items; the sheet explains that they must first be retrieved.
- **Layout:** Inventory now owns Combat loadout and Inventory sub-tabs. Browse library remains GM-only; Add item and Custom item remain available to owners. Sub-tab selection survives sheet rerenders.

## Remaining limitations and risks

1. **Not every item description is executable.** The library stores the descriptions and sources, but custom crafting modifications, armor plates and other attachments, conditional item abilities, ammunition and automatic consumable depletion still need dedicated rules. Item sheets retain editable numbers and descriptions. An item named like a standard item can still need review if it has custom modifications.
2. **Retrieval remains manual.** Moving a backpack item into carried inventory does not yet deduct the rulebook's 4 AP retrieval cost automatically. Remote storage cannot be assumed accessible. Kits in a backpack still count toward burden; other backpack contents are treated as non-combat storage.
3. **Burden exceptions need explicit modeling.** The base limit is 10 (a `system.combat.burdenLimit` override is respected), but starvation, exceptional carrying abilities, transports and unusual containers are not inferred from prose. Only the three named kit/rig types have automated storage allowances. Custom items can declare their suitability on the Item sheet.
4. **Damage is not universally intercepted.** Spidersilk's Fire vulnerability is automated in the system's defense damage prompt when Fire is selected. Direct HP edits, mixed damage types and third-party damage workflows need adjudication. The prompt uses the defense state captured when it was posted.
5. **Encounter timing uses Foundry's tracker.** The first round is the available application window for Mage Armor. Removing a combatant without ending the encounter, overlapping combats involving the same actor, or modules that bypass normal combat updates need live verification. AP/RP resets and encounter expiry require an active GM, matching the existing combat authority model.
6. **Legacy manual bonuses remain intentional data.** Slot enforcement cannot identify whether an old manually entered derived bonus was already intended to represent an armor item. Such bonuses should be reviewed if defenses look too high. Legacy extra equipped items are not deleted, but stop stacking outside valid slots.
7. **No live browser visual/multiplayer verification in this pass.** Full templates render in the test harness. Layout, remote image availability, networking, and interactions with installed Foundry modules should still be exercised in the live world. Changes are installed with a backup; no world character was altered during testing.

## Validation

- Real Actor preparation/update lifecycle: armor replacement, Manaweave current/max MP and previously spent MP, grant removal, repeat preparation, burden and recovery.
- Slot selection and cancellation, two-handed conflicts, deleted/moved equipment, container capacity and suitability, partial stacks, duplicate claims and single-rig enforcement.
- Mage frame effects and restrictions, modification locking, insufficient AP/MP, once-per-encounter application and combat-end expiration.
- Defense Fire damage, ordinary/forced movement, existing path/reversal/history checks and AP/RP reset tests.
- Existing character resource, advancement, source-removal, Excel import/rollback and template rendering regressions. The actual workbook still imports 13 items and reproduces its recorded stats and skills.
